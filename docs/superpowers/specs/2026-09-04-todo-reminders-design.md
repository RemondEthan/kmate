# 待办截止提醒 — Design Spec

Date: 2026-09-04
Status: Approved

## 背景

秘书里的「待办」目前只是会议/决定卡片里的一段话：没有截止日、没有 close、没有到点提醒。用户会加许多必须有截止时间的待办，希望从截止前 3 天起，只要没 close，就在每天登录、每天 10:00、每天 14:00 主动提醒；错过整点后上线也要补发。通知走聊天气泡，条目用加深批注标出，右侧知识页卡同步打开这些待办原文。

## 目标

- 可提醒的待办是 `knowledge/todos/` 下独立卡片，必有截止日和 `open` / `closed`。
- `open` 且本机今天 ≥ 截止日减 3 天 → 进入提醒窗口；过期未 close 继续提醒，直到 close。
- 触发点：进入聊天（登录，含脱机）、当天 10:00、当天 14:00。时区用本机。
- 错过整点再上线必须补发，不能因为人不在线就丢。同一时刻该发的多个点合并成**一条**气泡。
- 一条秘书侧气泡：摘要 + 每条待办一块加深批注；多条不拆成多条气泡。
- 提醒发出时，右侧沿用现有来源列表 + Markdown 预览，打开这批待办卡片。
- 会议/决定是待办的重要来源：归档时若「待办」不是「无」，必须同时写成 `knowledge/todos/` 卡片（每条问截止日）。

## 不在范围内

- 系统托盘、邮件、声音。
- Java 勾选 close、独立待办清单 UI。
- Java 去解析会议/决定卡片里的「待办：」一行来提醒（提醒只扫 `knowledge/todos/`）。
- 把历史上已经落盘、从未拆成 todo 卡的旧会议待办做一次性回填。
- 向量检索、改 WebSocket 协议。
- 到点叫醒模型生成提醒文案。
- Java 改待办状态或改 MEMORY.md。

## 待办卡片

路径（当前用户知识根下）：`knowledge/todos/YYYY-MM-DD-<标题短slug>.md`，日期为**截止日**。文件名规则与会议卡片相同：去掉 `/ \ : * ? " < > |`，空白改 `-`，过长截断；已存在则 `-2`、`-3`，不覆盖。

Java 只认列表字段（与会议卡同一风格）：

```
# 待办 · 申请 licence

- 截止：2026-09-10
- 状态：open
- 标题：申请 licence
```

| 字段 | 规则 |
|---|---|
| 截止 | `YYYY-MM-DD`，必填 |
| 状态 | 只允许 `open` / `closed` |
| 标题 | 可与一级标题「待办 · …」一致；缺标题时用一级标题去掉 `待办 · ` 前缀；再缺则用文件名 slug |

`状态` 不是 `open`、缺截止、日期无法解析、读盘失败：该文件不进入窗口，打警告，不影响其余卡片。目录不存在或为空：视为没有待办。

提醒扫描**只读** `knowledge/todos/`。会议/决定卡上的「待办：」仍是纪要，Java 不解析那一行。会上的事要进提醒，靠秘书归档时写成独立 todo 卡（见下节）。

秘书 skill：单独说「记一条待办」必须先问截止日，不齐不落盘；用户说「这个关了」只把对应 todo 卡改成 `closed`，不删文件。`KNOWLEDGE.md` / `memory_save` 指针可写，提醒扫描不依赖它们。

## 会议/决定 → todo 卡

归档会议或决定时，「待办」是必问槽（与现 skill 相同：没提就问；用户说没有 → 写「无」）。

「待办」不是「无」时，**未问清每条的截止日之前，整张会议/决定卡也不许落盘**（与现澄清门闩同一条：不齐不写卡、不 `memory_save`、不说已经记下）。

规则：

1. 把「待办」拆成一条一事。一段话里有多件，拆成多张 todo 卡。
2. 每条必须有截止日。没给就问；多条可以并列问截止。
3. 齐了先按现规则写会议/决定卡（「待办：」一行保留纪要原文或拆开后的短列表）。
4. 再为每条写一张 `knowledge/todos/` 卡：`状态=open`，标题用该条事项，截止用问到的日期。可选加一行 `- 来源：knowledge/meetings/…` 或 `knowledge/decisions/…`（提醒解析可忽略此字段）。
5. `KNOWLEDGE.md` 与 `memory_save` 指针带上会议卡路径；todo 卡路径一并写上更好，提醒不依赖指针。

用户说「待办没有」：会议卡照常落盘，不建 todo 卡。

本期不对旧会议卡做回填。已经归档、从未拆成 todo 的待办，除非用户再让秘书补记，否则不进提醒。

## 谁该被提醒

本机 `LocalDate`。同时满足才进窗口：

1. 解析成功且 `状态=open`
2. `today >= 截止 - 3 天`（含截止当天与逾期）

排序：截止日升序，同一天按标题升序。

窗口为空：不发气泡，也**不**改账本。因此 09:00 登录时尚无待办、09:30 才建卡，10:00 仍会响。某个点已经发出之后才新建的待办：等下一个点，不回补刚发过的点。

## 三个点与补发账本

三个点：`LOGIN`（进入聊天）、`TEN`（当天 10:00）、`FOURTEEN`（当天 14:00）。

账本是该用户知识根下的小文件 `<username>/.todo-reminder-ledger`（不在 `knowledge/` 下，不当卡片、不进 `/find`）。记录「哪一个本地日期的哪些点已经**发出过**提醒」。坏了或读不到：当成今天尚未发过（最多重复提醒一次）。

进入聊天时（含脱机）：

1. 扫描并筛窗口、排序。
2. 计算今天尚未发出、且当前时刻已到达或超过的点：
   - `LOGIN` 今天未发 → 计入
   - 现在 ≥ 10:00 且 `TEN` 今天未发 → 计入
   - 现在 ≥ 14:00 且 `FOURTEEN` 今天未发 → 计入
3. 窗口非空且待发点非空 → **一次**发送，并把这些点全部记为已发。
4. 10:01 登录且今天 10:00 未发过：`LOGIN` 与 `TEN` 一起记上，只出一条气泡。
5. 09:00 登录只发并只记 `LOGIN`；人已在线则排到下一个 10:00 / 14:00，到点再各发一次（窗口仍非空时）。
6. 15:00 才登录：三个点合并成一条，全部记账。

跨日：账本按日期，昨天的点不影响今天。

## 气泡（含多条）

永远一条秘书侧 `ASSISTANT` 气泡（复用头像/名字/时间，不是系统灰条）。不新增 `Sender`。

结构：

1. 摘要：`还有 N 条待办待处理`（N 为本次窗口条数）。
2. N 块加深底色批注，顺序与窗口排序一致。每块：标题；`截止 YYYY-MM-DD`；若今天已过截止则同行加 `已逾期`。不把卡片全文塞进气泡。
3. 点某一块 = 右侧选中并打开对应路径（与点来源芯片相同）。

20 条仍是一条气泡，批注在气泡内向下排，随会话滚动。

`Message.content` 用固定文本入聊天历史，重开后能还原同样的块：

```
还有 3 条待办待处理
- 申请 licence | 截止 2026-09-10 | 已逾期 | knowledge/todos/2026-09-10-申请-licence.md
- 发周报 | 截止 2026-09-12 | knowledge/todos/2026-09-12-发周报.md
```

规则：首行摘要；其后每行一条，以 `- ` 开头，字段用 ` | ` 分隔：标题、`截止 YYYY-MM-DD`、可选 `已逾期`、相对路径。未逾期的行没有「已逾期」段。`HistoryCodec` 不改字段，只存这串 `content`。列表渲染时若能按此格式解析，画加深块；解析失败则当普通秘书文本。

## 右侧页卡

复用现有 `KnowledgePane`（来源芯片 + `MarkdownView`）和 `CitationTurn`。`KnowledgePathExtractor` 已匹配 `knowledge/**.md`，待办路径无需改正则。

提醒发出时：

- 秘书**没有**进行中的提问：用这 N 条相对路径覆盖 `shown`，`knowledgeVisible = true`，`open` **最紧急一条**（排序后第一条，不是最后一条）。上沿芯片顺序与气泡批注一致。
- 秘书**正在回答**：气泡照发并记账；**不改**右侧。进行中若多次到点，只保留**最后一批**待办路径。等 `onComplete`：若本问 `pending` 非空，仍按知识页规则用检索列表覆盖并 `open` 最后一条；若 `pending` 为空，再用这批待办路径覆盖并 `open` 最紧急一条。

点芯片：现有 `open`。文件缺失/过大/拒绝：现有读失败文案，芯片保留，不影响气泡。

顶栏「知识库」仍只切换显示。

## 组件

盘上的卡片是唯一真相。Java 只读、只提醒，不改 `open` / `closed`。

| 单元 | 职责 |
|---|---|
| `TodoCard` / `TodoCardParser` | 读 `knowledge/todos/*.md`，抽出标题、截止、状态、路径；坏文件跳过 |
| `TodoReminderPolicy` | 窗口判定；按截止、标题排序 |
| `ReminderLedger` | 读写「某日哪些点已发出」 |
| `TodoReminderService` | 进聊天算补发；在线排下一个 10:00 / 14:00；有窗口且有未发点则交出卡片 + 待记账的点 |
| 气泡 / `AssistantBubble` | `ASSISTANT` + 加深批注块；点击打开路径 |
| `ChatController` | 收到批次后追加消息、写历史、按上节更新或推迟页卡 |
| kelsy-knowledge skill | 单独待办落盘与 close；会议/决定归档时拆写 todo 卡 |

调度：进聊天后用本机时钟排到下一个 10:00 或 14:00（过了 14:00 则排次日 10:00），到点在 FX 线程投递。不轮询模型。离开聊天/退出时取消调度。

## 数据流

```
enterChat
  → scan knowledge/todos → filter window → sort
  → slots = due and not yet fired today
  → if todos nonempty && slots nonempty:
       post one ASSISTANT reminder
       ledger.mark(today, slots)
       ask in flight? defer pane : shown=todo paths, open first
  → schedule next TEN/FOURTEEN

clock TEN/FOURTEEN
  → same scan/filter
  → if todos nonempty && this slot not fired:
       post one reminder, mark slot, pane as above

secretary onComplete
  → pending nonempty? citation pane as today
  : deferred reminder paths? shown=those paths, open first
```

## 出错

- 目录缺失/空：不发、不记账。
- 单卡坏：跳过并警告。
- 账本坏：视为今天未发。
- 预览读失败：现有文案。
- 回答中途到点：气泡 + 记账，页卡推迟。

## 测试

不启 JavaFX Stage：

- 解析：齐字段 / 缺截止 / 坏日期 / `closed`。
- 窗口：截止前第 4 天不进；前第 3 天、当天、逾期且 `open` 要进；`closed` 不进。
- 补发：10:01 登录且 `TEN` 未发 → 一次发送，账本记 `LOGIN`+`TEN`；09:00 登录只记 `LOGIN`，10:00 再发一次。
- 空窗口：不发、不记账。
- 排序：截止近的在前，同日按标题。
- 存档文本 ↔ 条目（条数、路径、是否逾期）往返一致。

手工：建 2 张未关卡（一张已进窗口、一张截止在 4 天后）→ 登录只看到窗口内那张；改系统时间或等到 10:00 再出一条；把窗口内的改成 `closed` 后下一拍不再出现；错过 10:00 再登录只补一条；点批注打开右侧对应卡。`/note` 一场带两条待办的会议 → 秘书先问截止 → 盘上有会议卡 + 两张 todo 卡；只写「待办：周五交」但没建 todo 卡的旧会议不进登录提醒。

## 风险（接受）

秘书若漏写截止或写错字段，该条永远不会进窗口，只靠日志发现。账本损坏可能导致同一天重复一条提醒。提醒不经过模型，文案固定。
